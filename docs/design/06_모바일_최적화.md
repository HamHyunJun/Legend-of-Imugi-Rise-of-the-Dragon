# 06. 모바일 최적화 계획

## 1. 목표 수치

| 항목 | 목표 |
|---|---|
| 프레임 | **30fps 고정**(기본). 고사양 기기 옵션으로 60fps 선택 가능 |
| 최소 사양 기준 | Android 8.0+, RAM 3GB, 2019~2020년 보급형 칩셋(Adreno 610 / Mali-G52급) |
| 연속 플레이 | 최소 사양 기기에서 30분 연속 플레이 시 스로틀링으로 인한 프레임 저하 없음 |
| 메모리 | 게임 전체 사용량 800MB 이하(최소 사양 기준) |
| 앱 용량 | MVP AAB 150MB 이하, 본편도 Play 기본 한도(200MB) 안 목표. 초과 시 Play Asset Delivery 검토 |
| 지역 로딩 | 5초 이내 |

30fps를 기본으로 하는 이유: 이 장르(탐험·육성)에서는 60fps보다 발열과 배터리 이득이 크다. 프레임을 고정하면 발열로 인한 들쭉날쭉한 프레임보다 체감이 좋다.

## 2. 렌더링

### 2.1 렌더러 선택
- **Compatibility 렌더러(OpenGL ES 3.0)를 기본**으로 한다. 저사양 Android 기기 지원 폭이 가장 넓고, 로우폴리 + 픽셀 텍스처 스타일에는 고급 기능이 필요 없다.
- M1에서 같은 테스트 씬을 Mobile 렌더러(Vulkan)와 비교 측정하고, 최종 결정은 그 결과로 확정한다. 이후에는 바꾸지 않는다.

### 2.2 그래픽 스타일과 최적화를 한 번에
"로우폴리 3D + 픽셀 텍스처"는 그 자체로 최적화 수단이다.
- **텍스처**: 캐릭터 128~256px, 환경 타일 64~256px, 필터링 Nearest(픽셀 느낌), 밉맵은 원경용 환경 텍스처에만.
- **텍스처 아틀라스**: 지역별 환경 소품을 1~2장의 아틀라스로 묶어 머티리얼 수를 줄인다(드로우콜 감소).
- **압축**: ETC2 압축(Android 표준). 픽셀 아트가 뭉개지는 UI·캐릭터 핵심 텍스처만 무압축 예외.
- **조명**: 실시간 광원은 방향광 1개만. 그림자는 플레이어/보스만 블롭 그림자(원형 데칼) 또는 저해상도 단일 그림자맵. 환경 음영은 **버텍스 컬러와 텍스처에 미리 칠해 넣는다**(라이트맵 의존 최소화).
- **셰이더**: 언릿(unlit) 또는 단순 램버트 기반 커스텀 셰이더 1~2종으로 통일. 툰 느낌의 계단식 음영은 셰이더 한 종에서 처리.
- **후처리 없음**: 블룸, SSAO, SSR, 글로우, 볼륨 안개 사용하지 않음. 안개는 거리 기반 단순 안개만.
- **해상도 스케일**: 3D 렌더 해상도 0.75 기본(설정에서 0.6/0.75/1.0). 픽셀 스타일이라 낮은 해상도가 오히려 어울리고, UI는 원래 해상도로 그린다.

### 2.3 폴리곤과 드로우콜 예산

| 대상 | 삼각형 수 |
|---|---|
| 이무기/용 (플레이어) | 3,000 ~ 5,000 |
| 보스 | 5,000 ~ 8,000 |
| NPC | 800 ~ 1,500 |
| 일반 적 | 500 ~ 1,500 |
| 화면 전체 (동시에 보이는 것) | 100,000 이하 |
| 드로우콜 | 지상 150 이하, 비행 중 200 이하 |

## 3. 비행을 고려한 월드 구성

비행은 시야가 넓어져 성능 부담이 가장 큰 부분이다. 그래서 기획 단계부터 다음을 고정한다.

- **지역 씬 단위 월드**: 한 번에 하나의 지역만 메모리에 올린다. 지역 크기 상한은 대략 가로세로 500m 수준.
- **지역 내부 구역 분할**: 지역을 3~6개 구역 노드로 나누고, 플레이어 위치 기준으로 먼 구역의 상세 소품을 숨긴다(`visibility_range` 활용).
- **LOD**: 건물·나무·바위는 2단계 LOD(상세 / 저폴리 실루엣). 원경 산맥은 단일 저폴리 메시 또는 하늘 배경에 그려 넣은 그림.
- **거리 안개**: 비행 고도에 따라 안개 거리를 조절해 원경을 자연스럽게 가린다. 동양화 같은 운무 연출로 미술적으로도 활용.
- **식생**: 풀·작은 나무는 `MultiMeshInstance3D`로 일괄 그리기. 바람 흔들림은 버텍스 셰이더로.
- **오클루전**: 마을·동굴처럼 가림이 많은 곳만 `OccluderInstance3D` 사용. 탁 트인 숲과 하늘에는 쓰지 않음.
- **비행 경계와 높이 상한**: 지역마다 정해 렌더링 범위를 예측 가능하게 유지.

## 4. 로딩과 메모리

- **지역 로딩**: `ResourceLoader.load_threaded_request`로 백그라운드 로딩하며 로딩 화면(설화 그림 + 팁) 표시.
- **이전 지역 해제**: 지역 전환 시 이전 씬을 완전히 해제(`queue_free`)한 뒤 다음 씬을 올린다. 둥지는 자주 오가므로 가볍게 유지.
- **공용 리소스 상주**: 플레이어, UI, 공용 이펙트, 공용 사운드는 상주. 지역 전용 에셋만 교체.
- **오디오**: 배경음은 OGG 스트리밍, 효과음은 짧은 WAV/OGG 미리 로드. 동시 재생 수 제한(효과음 16채널).

## 5. 오브젝트 풀링

다음은 생성·삭제 대신 풀에서 꺼내 쓰고 돌려놓는다.
- 투사체(브레스, 독침, 화살), 피격 이펙트, 데미지 숫자, 기운 획득 문양
- 일반 적(지역 진입 시 `pool_size`만큼 미리 생성, 비활성 상태로 대기)
- 수집 아이템, 파티클 이펙트

파티클은 `GPUParticles3D` 대신 **`CPUParticles3D`** 를 기본으로 한다(Compatibility 렌더러와 저사양 GPU 호환성). 이펙트당 입자 수는 30개 이하를 기준으로 하고, 텍스처 시트 애니메이션과 메시 이펙트(회전하는 저폴리 메시)를 적극 활용한다.

## 6. 물리와 로직

- **물리**: 플레이어·NPC·적은 `CharacterBody3D` + 캡슐 충돌체. 리지드바디는 연출용 소품 몇 개로 한정. 환경 충돌은 단순화된 박스/볼록 충돌체(렌더 메시를 충돌체로 쓰지 않음).
- **물리 틱**: 30Hz(프레임과 동일). 비행·수영 이동은 물리 엔진 대신 직접 속도 계산.
- **뱀 몸통 애니메이션**: 마디 수를 형태별 12~20개로 제한. 마디 위치 계산은 머리 경로 기록 배열 기반(물리 조인트 사용 안 함).
- **AI 업데이트 빈도**: 플레이어에서 먼 적은 AI 판단을 0.2~0.5초 간격으로만 갱신. 화면 밖 적은 비활성.
- **NPC**: 마을 NPC는 화면에 보이거나 근처일 때만 애니메이션 처리(`VisibleOnScreenNotifier3D`).
- **레이캐스트 최소화**: 감지는 거리·각도 판정 먼저, 레이캐스트는 최종 확인 때 1회.

## 7. 발열·배터리 관리

- 프레임 고정(30fps) + 렌더 해상도 스케일.
- **메뉴·대화·둥지 UI 열림 시** 3D 렌더 빈도를 낮춤(배경 정지 화면 또는 15fps).
- **앱 백그라운드 시** 즉시 일시정지 및 자동 저장, 오디오 정지.
- **그래픽 품질 프리셋 2단계**(낮음/보통). 낮음: 해상도 0.6, 식생 밀도 50%, 그림자 끄기, LOD 거리 축소. 첫 실행 시 기기 메모리·GPU 이름 기준으로 자동 선택.

## 8. UI 최적화

- UI는 2D `Control` 노드, 3D 화면과 분리. 대화창·메뉴는 열 때만 인스턴스화.
- 폰트: 한글 비트맵 느낌 폰트 1종 + 본문 폰트 1종. 필요한 글자만 포함한 서브셋 폰트로 용량 절감(대사 데이터에서 사용 글자 추출).
- 다양한 화면비(18:9 ~ 21:9, 태블릿 4:3) 대응: 앵커 기반 배치, 노치 영역 회피(Safe Area).

## 9. 측정과 점검 방법

- **마일스톤마다 실기기 측정**(04 문서). Godot 프로파일러 + 원격 디버그로 프레임 시간, 드로우콜, 메모리 확인.
- 게임 내 디버그 오버레이(개발 빌드 전용): FPS, 드로우콜, 활성 적 수, 메모리.
- **성능 점검 체크리스트** (M10 및 각 지역 추가 시)
  - [ ] 최소 사양 기기 30fps 유지 (지상, 비행, 보스전 각각)
  - [ ] 30분 연속 플레이 후 프레임 유지, 기기 표면 과열 없음
  - [ ] 지역 전환 10회 반복 후 메모리 증가 없음
  - [ ] 드로우콜·삼각형 예산 준수
  - [ ] 앱 백그라운드 → 복귀 시 정상 재개 및 자동 저장 확인
  - [ ] 저장 중 강제 종료 후 세이브 복구 확인
