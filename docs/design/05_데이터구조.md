# 05. 게임 데이터 구조

## 1. 기본 방침

| 구분 | 형식 | 이유 |
|---|---|---|
| **콘텐츠 정의 데이터** (오행, 진화, 스킬, 지역, NPC, 대화, 퀘스트, 둥지, 적, 음양 규칙) | `res://data/` 아래 **JSON** | 텍스트라 Git 비교가 쉽고, 코드 없이 추가·수정 가능. 스프레드시트나 AI 도구로 대량 작성하기 쉬움. 업데이트 시 파일만 추가 |
| **시각 에셋 묶음** (용 부위 조합, 둥지 테마 소품 세트, 조명 프리셋) | Godot **씬(.tscn) / 리소스(.tres)** | 에디터에서 눈으로 보며 배치해야 하는 것. JSON에서는 경로 문자열로만 참조 |
| **세이브 데이터** | `user://` 아래 **JSON** | 버전 관리와 마이그레이션이 쉬움 |

- JSON 정의는 게임 시작 시 `DataRegistry`가 모두 읽어 타입이 있는 GDScript 객체로 변환한다. 전체 텍스트 데이터는 MVP 기준 수백 KB 수준이라 시작 시 일괄 로드해도 부담이 없다.
- 개발용 **데이터 검증 스크립트**(에디터 툴 스크립트)를 만들어 다음을 검사한다: ID 중복, 존재하지 않는 ID 참조, 알 수 없는 조건/효과 타입, 경로가 없는 에셋, 퀘스트 단계 도달 불가.

## 2. 폴더 구조

```
res://
├── data/                      # 콘텐츠 정의(JSON)
│   ├── elements.json          # 오행 정의
│   ├── forms/                 # 진화 형태 (형태당 1파일)
│   │   ├── form.wood.yang.json
│   │   └── form.wood.yin.json
│   ├── skills/
│   ├── regions/               # 지역당 1파일 (게이트·지점 포함)
│   ├── npcs/
│   ├── dialogues/             # 대화 (NPC 또는 사건 단위)
│   ├── quests/
│   ├── enemies/
│   ├── nest.json              # 둥지 단계·테마
│   ├── yinyang.json           # 음양 등급·상한·성향 특성
│   └── progression.json       # 성장 단계, 레벨 곡선
├── assets/                    # 모델·텍스처·사운드
├── scenes/
│   ├── regions/               # 지역 씬
│   ├── characters/            # 이무기, 용 리그, NPC
│   ├── nest/                  # 둥지 단계 지형, 테마 소품 세트
│   └── ui/
├── scripts/
│   ├── core/                  # GameState, DataRegistry, EventBus, SaveSystem
│   ├── logic/                 # Condition, Effect, QuestRunner, DialogueRunner
│   ├── player/
│   ├── combat/
│   └── world/
└── tools/                     # 데이터 검증 등 에디터 도구
```

## 3. ID 규칙

- 모든 정의는 **점(.)으로 구분한 소문자 영문 ID**를 갖는다. 화면 표시 이름은 별도 필드(`name`)이고 ID는 절대 바꾸지 않는다(세이브 호환).
- 접두어로 종류를 구분한다.

| 종류 | 예시 |
|---|---|
| 오행 | `wood`, `fire`, `earth`, `metal`, `water` |
| 형태 | `form.imugi`, `form.wood.yang`(청룡), `form.wood.yin`(독목룡), `form.hidden.heaven`(천룡) |
| 스킬 | `skill.wood.vine_heal` |
| 지역 | `region.jamryong_cave`, `region.solmoe_village`, `region.cheongsong_valley` |
| NPC | `npc.dani`, `npc.park` |
| 대화 | `dlg.dani.first_meet` |
| 퀘스트 | `quest.main.find_dolsoe` |
| 플래그 | `flag.chikbeom.allied` |
| 카운터 | `counter.wildlife_saved` |

## 4. 공통 조건(Condition)과 효과(Effect)

진화 해금, 지역 게이트, 퀘스트 개방, 대화 분기, NPC 반응, 둥지 단계, 업적이 **모두 같은 조건 형식**을 쓴다. 보상도 모두 같은 효과 형식을 쓴다. 이것이 확장성의 핵심이다. 새 시스템을 붙일 때 조건·효과 타입만 추가하면 된다.

### 4.1 조건 타입

```jsonc
// 단일 조건
{ "type": "has_orb", "element": "wood" }

// 조합
{ "all": [ {...}, {...} ] }
{ "any": [ {...}, {...} ] }
{ "not": {...} }
```

| type | 매개변수 | 의미 |
|---|---|---|
| `flag` | `id`, `value`(기본 true) | 플래그 값 비교 |
| `counter` | `id`, `min`/`max` | 카운터 범위 |
| `level` | `min` | 레벨 이상 |
| `has_orb` | `element` | 보주 보유 |
| `orb_count` | `min` | 보주 개수 |
| `tendency` | `min`/`max` | 성향 범위(-100~100) |
| `yang_total` / `yin_total` | `min` | 누적값 |
| `form_unlocked` | `id` | 형태 해금 여부 |
| `forms_unlocked_count` | `polarity`(yang/yin/any), `element`(선택), `min` | 조건에 맞는 해금 형태 수 |
| `elements_with_form` | `min` | 형태를 1개 이상 해금한 속성 수 |
| `current_form` | `id` 또는 `element`/`polarity` | 현재 장착 형태 |
| `quest_state` | `id`, `state`(inactive/active/completed), `stage`(선택) | 퀘스트 상태 |
| `relation` | `npc`, `min`/`max` | NPC 관계 |
| `village_mood` | `region`, `is` | 마을 분위기 |
| `growth_stage` | `min` | 성장 단계(새끼, 성체, 활강, 용, 각성, 신격) |
| `ability` | `id` | 이동 능력 보유(swim, climb, glide, fly, fast_fly) |
| `nest_stage` | `min` | 둥지 단계 |

### 4.2 효과 타입

| type | 매개변수 | 의미 |
|---|---|---|
| `set_flag` | `id`, `value` | 플래그 설정 |
| `add_counter` | `id`, `amount` | 카운터 증가 |
| `add_exp` | `amount` | 경험치 |
| `yinyang` | `polarity`, `grade`(micro/small/medium/large/huge), `source`(선택, 반복 상한 그룹) | 음양 획득. 실제 수치는 `yinyang.json`의 등급표에서 결정 |
| `give_orb` | `element` | 보주 지급 |
| `unlock_ability` | `id` | 이동 능력 해금 |
| `relation` | `npc`, `amount` | 관계 변화 |
| `quest` | `id`, `action`(start/advance/complete/fail), `stage`(선택) | 퀘스트 상태 변경 |
| `give_item` | `id`, `count` | 아이템 |
| `region_state` | `region`, `state` | 지역 상태 전환(예: 청송골 시듦 → 회복) |
| `play_sequence` | `id` | 연출 재생(첫 승천 등) |
| `notify_altar` | - | "제단이 공명한다" 알림 |

- 음양 획득은 숫자를 직접 쓰지 않고 **등급**만 쓴다. 밸런스를 바꿀 때 `yinyang.json` 한 곳만 고치면 된다.

## 5. 정의 데이터 스키마와 예시

### 5.1 오행 (`elements.json`)

```json
[
  {
    "id": "wood",
    "name": "목(木)",
    "color": "#3FAF6A",
    "orb_icon": "res://assets/ui/orb_wood.png",
    "field_ability": "ability.growth",
    "nest_theme": "theme.wood",
    "generates": "fire",
    "overcomes": "earth"
  }
]
```

- `generates`/`overcomes`(상생/상극)는 오행황룡의 연계 순서와 향후 속성 상성에 쓴다. 상성 피해 보정은 MVP에서 쓰지 않지만 필드는 둔다.
- **새 오행 추가**(예: 뇌): 이 배열에 항목 1개 + 보주 아이콘 + 형태 파일 2개 + 테마 세트 1개 + 지역 파일. 코드 수정 없음.

### 5.2 진화 형태 (`forms/*.json`)

```json
{
  "id": "form.wood.yang",
  "name": "청룡",
  "element": "wood",
  "polarity": "yang",
  "tier": "base",
  "unlock": {
    "all": [
      { "type": "has_orb", "element": "wood" },
      { "type": "tendency", "min": 20 }
    ]
  },
  "unlock_quest": null,
  "first_ascension": { "level_min": 10 },
  "visual": "res://scenes/characters/dragon/forms/wood_yang.tscn",
  "stat_mod": { "hp": 1.10, "atk": 0.95, "def": 1.0 },
  "skills": {
    "element": "skill.wood.vine_heal",
    "polarity": "skill.yang.guard",
    "ultimate": "skill.wood_yang.ult_rebirth"
  },
  "move_trait": "trait.hover_regen",
  "nest_theme_default": "theme.wood",
  "codex": { "hint": "숲의 신령에게 자비를 베푼 이무기", "lore": "dlg.codex.wood_yang" }
}
```

히든 형태 예시(조건 + 전용 퀘스트):

```json
{
  "id": "form.hidden.chaos",
  "name": "혼돈룡",
  "element": null,
  "polarity": "balance",
  "tier": "hidden",
  "unlock": {
    "all": [
      { "type": "yang_total", "min": 800 },
      { "type": "yin_total", "min": 800 },
      { "type": "tendency", "min": -10, "max": 10 },
      { "type": "forms_unlocked_count", "polarity": "yang", "min": 1 },
      { "type": "forms_unlocked_count", "polarity": "yin", "min": 1 },
      { "type": "flag", "id": "flag.ending.coexist" }
    ]
  },
  "unlock_quest": "quest.hidden.taeguk_rift",
  "special": "stance_switch"
}
```

- `unlock`을 만족하면 `unlock_quest`가 열리고, 퀘스트 완료 효과로 형태가 해금된다. `unlock_quest`가 없으면 제단 방문 시 바로 해금.
- `special`은 일반 스킬 구조로 표현하기 어려운 고유 기능(태세 전환, 오행 순환 등)을 가리키는 키. 해당 기능은 코드 모듈로 구현하고 키로 연결한다.

### 5.3 스킬 (`skills/*.json`)

```json
{
  "id": "skill.wood.vine_heal",
  "name": "치유의 덩굴",
  "slot": "element",
  "cooldown": 8.0,
  "ground": { "scene": "res://scenes/skills/vine_heal.tscn", "damage": 0.6, "root_time": 1.5, "heal_allies": 0.08 },
  "air":    { "scene": "res://scenes/skills/vine_heal_air.tscn", "damage": 0.5 },
  "tags": ["control", "heal"]
}
```

- 수치는 공격력 대비 배율로 적어 레벨 곡선과 분리한다.
- 지상(`ground`)과 공중(`air`) 변형을 한 파일에 둔다.

### 5.4 지역 (`regions/*.json`)

```json
{
  "id": "region.cheongsong_valley",
  "name": "청송골",
  "scene": "res://scenes/regions/cheongsong_valley.tscn",
  "enter": { "type": "quest_state", "id": "quest.main.prologue", "state": "completed" },
  "states": ["withered", "restored"],
  "default_state": "withered",
  "fly_ceiling": 120.0,
  "music": { "withered": "res://assets/bgm/forest_dark.ogg", "restored": "res://assets/bgm/forest.ogg" },
  "gates": [
    { "id": "gate.cheongsong.vine_01", "kind": "vine", "requires": { "type": "has_orb", "element": "wood" } }
  ],
  "yinyang_cap_group": "cheongsong",
  "exits": [
    { "to": "region.solmoe_village", "spawn": "from_valley" }
  ]
}
```

- 씬 안의 게이트 오브젝트는 `gate_id` 하나만 가지고, 조건은 데이터에서 읽는다. 레벨 디자이너는 씬에 오브젝트를 놓고 ID만 적으면 된다.
- 지역 상태(`states`)는 씬 내 노드 그룹 표시/숨김과 조명·음악 전환으로 처리한다(별도 씬 복제 없음).

### 5.5 NPC (`npcs/*.json`)

```json
{
  "id": "npc.park",
  "name": "약초꾼 박씨",
  "job": "약초꾼",
  "personality": ["걱정 많음", "정직함"],
  "relations": { "npc.dolsoe": "아들", "npc.choi": "빚" },
  "home_region": "region.solmoe_village",
  "model": "res://scenes/characters/npc/villager_m_old.tscn",
  "relation_start": 0,
  "reactions": [
    { "when": { "type": "relation", "npc": "npc.park", "max": -40 }, "behavior": "flee", "bark": "dlg.park.bark_afraid" },
    { "when": { "type": "relation", "npc": "npc.park", "min": 40 },  "behavior": "greet", "bark": "dlg.park.bark_trust" }
  ],
  "dialogue_entry": [
    { "when": { "type": "quest_state", "id": "quest.main.find_dolsoe", "state": "active" }, "dialogue": "dlg.park.dolsoe_progress" },
    { "when": null, "dialogue": "dlg.park.default" }
  ]
}
```

- `reactions`와 `dialogue_entry`는 위에서부터 처음 맞는 조건 하나를 고른다.
- `behavior`는 미리 정한 행동 세트(greet, idle, flee, hide, follow)만 사용한다.

### 5.6 대화 (`dialogues/*.json`)

```json
{
  "id": "dlg.chikbeom.confront",
  "speaker_default": "npc.chikbeom",
  "nodes": {
    "start": {
      "text": "이무기 따위가 내 숲에 무슨 볼일이냐.",
      "choices": [
        { "text": "[결투] 돌쇠를 풀어줘라.", "next": "duel",
          "effects": [ { "type": "yinyang", "polarity": "yang", "grade": "medium" } ] },
        { "text": "[거래] 최 진사의 창고를 털어주겠다.", "next": "deal",
          "effects": [ { "type": "yinyang", "polarity": "yin", "grade": "medium" },
                       { "type": "set_flag", "id": "flag.chikbeom.allied", "value": true } ] },
        { "text": "[단이] (단이의 눈치를 본다)", "next": "dani_hint",
          "show_if": { "type": "relation", "npc": "npc.dani", "min": 30 } }
      ]
    },
    "duel": { "text": "좋다, 덤벼라!", "effects": [ { "type": "quest", "id": "quest.main.chikbeom", "action": "advance", "stage": "duel" } ], "end": true }
  }
}
```

- 대사 텍스트는 MVP에서 JSON에 직접 쓰고, 현지화가 필요해지면 `text`를 번역 키로 바꾸는 변환 스크립트를 쓴다(Godot의 번역 CSV 활용).
- 선택지의 `show_if`로 조건부 선택지를 만든다.

### 5.7 퀘스트 (`quests/*.json`)

```json
{
  "id": "quest.main.find_dolsoe",
  "name": "사라진 돌쇠",
  "category": "main",
  "region": "region.cheongsong_valley",
  "available": { "type": "quest_state", "id": "quest.main.prologue", "state": "completed" },
  "giver": "npc.park",
  "stages": [
    { "id": "search", "desc": "숲에서 돌쇠의 흔적을 찾자",
      "objectives": [ { "kind": "inspect", "target": "clue.footprint", "count": 3 } ],
      "on_complete": [ { "type": "quest", "id": "quest.main.find_dolsoe", "action": "advance", "stage": "camp" } ] },
    { "id": "camp", "desc": "산적 진지로 가자",
      "objectives": [ { "kind": "reach", "target": "area.bandit_camp" } ],
      "on_complete": [ { "type": "quest", "id": "quest.main.chikbeom", "action": "start" } ] }
  ],
  "rewards": [ { "type": "add_exp", "amount": 120 } ]
}
```

- 목표 종류(`kind`)는 한정한다: `talk`, `inspect`, `reach`, `defeat`, `collect`, `deliver`, `escort`, `choose`(대화 선택), `flag`(임의 조건 대기), `minigame`. 퍼즐·잠입은 해당 기믹 스크립트가 끝날 때 플래그를 세우고 `flag` 목표로 연결한다.
- 분기 퀘스트는 단계(`stage`)를 건너뛰는 효과로 표현한다(양 루트 단계, 음 루트 단계를 모두 정의하고 선택 효과로 다음 단계를 지정).

  "scene": "res://scenes/enemies/bandit.tscn",
  "level_offset": 0,
  "stats": { "hp": 1.0, "atk": 0.8 },
  "ai": "melee_basic",

- `pool_size`는 오브젝트 풀 초기 크기.

## 6. 런타임 상태 (`GameState`)

정의 데이터는 읽기 전용이고, 변하는 값은 모두 `GameState` 한 곳에 모은다. 세이브는 `GameState`를 그대로 직렬화한 것이다.

```gdscript
# 개념 구조 (실제 구현 시 타입 클래스로 분리)
var player := {
    "name": "미르",
    "level": 1, "exp": 0,
    "growth_stage": "hatchling",        # hatchling/adult/glider/dragon/awakened/divine
    "abilities": ["walk"],
    "current_form": "form.imugi",
    "unlocked_forms": [],
    "bond": {},                         # form_id -> 교감 등급
    "accessories": [],
}
var yinyang := { "yang_total": 0, "yin_total": 0, "tendency": 0, "micro_used": {} }  # micro_used: "cheongsong:1:yang" -> 사용량
var orbs := []                          # ["wood"]
var flags := {}                         # flag_id -> 값
var counters := {}                      # counter_id -> int
var quests := {}                        # quest_id -> { "state": "active", "stage": "search", "progress": {...} }
var relations := {}                     # npc_id -> int
var regions := {}                       # region_id -> { "state": "withered", "visited": true, "discovered": [...] }
var nest := { "stage": 1, "theme": null, "unlocked_themes": ["theme.base"], "slots": {} }
var inventory := {}                     # item_id -> count
var codex := { "forms_seen": [], "enemies": [], "treasures": [] }
var records := { "play_time": 0, "flight_challenges": {} }
var location := { "region": "region.jamryong_cave", "spawn": "nest" }
```

- `nest.theme`이 `null`이면 현재 형태의 기본 테마를 따른다(02 문서 4.2의 자동 추천 규칙).
- 모든 상태 변경은 효과(Effect) 실행 또는 전용 함수를 통해서만 하고, 변경 시 `EventBus`로 신호를 보낸다(`flag_changed`, `yinyang_changed`, `orb_gained`, `form_unlocked` 등). UI와 NPC 반응은 이 신호를 듣고 갱신한다.

## 7. 세이브 파일

```json
{
  "save_version": 1,
  "game_version": "0.1.0",
  "saved_at": "2026-11-16T15:30:00",
  "slot": "auto",
  "checksum": "…",
  "state": { "player": {}, "yinyang": {}, "orbs": [], "flags": {}, "...": "..." }
}
```

- **파일**: `user://saves/auto.json`, `user://saves/manual_1.json`, 각각 직전 저장본 `*.bak` 유지.
- **쓰기 방식**: 임시 파일에 쓴 뒤 이름 변경(저장 중 앱 종료 시 손상 방지). 읽기 실패 시 `.bak`으로 복구.
- **체크섬**: 손상 감지용(보안 목적 아님, 로컬 싱글플레이라 조작 방지는 하지 않는다).
- **버전 마이그레이션**: `save_version`이 낮으면 `SaveMigrations`의 단계별 함수(v1→v2→…)를 순서대로 적용한다. 정의 데이터에서 사라진 ID는 무시하고 경고만 남긴다.
- **자동 저장 시점**: 둥지 휴식, 지역 전환, 퀘스트 단계 완료, 진화 해금, 앱이 백그라운드로 갈 때(`NOTIFICATION_APPLICATION_PAUSED`).
- 설정(음량, 그래픽 품질)은 세이브와 분리해 `user://settings.cfg`(ConfigFile)에 저장.

## 8. 확장 시나리오 점검

| 추가하려는 것 | 필요한 작업 | 코드 수정 |
|---|---|---|
| 새 지역 | 지역 JSON + 지역 씬 + NPC/대화/퀘스트 JSON | 없음 (새 기믹이 있으면 기믹 스크립트 1개) |
| 새 퀘스트 | 퀘스트 JSON + 대화 JSON | 없음 |
| 새 기본 진화 | 형태 JSON + 스킬 JSON 3개 + 부위 씬 | 없음 |
| 새 히든 진화 | 형태 JSON + 해금 퀘스트 + 고유 기능 모듈 | `special` 모듈 1개 |
| 새 오행 | `elements.json` 항목 + 형태 2종 + 테마 + 지형 능력 | 지형 능력 오브젝트 스크립트 1개 |
| 새 조건 종류 | Condition 평가 함수에 타입 1개 추가 | 1곳 |
| 업적 시스템 | 업적 JSON(조건 + 보상 효과) + UI | 업적 관리자 1개(EventBus 구독) |
